SenderSend from a terminal

Replace FILE with the file to send:

curl {{.Base}} -T FILE

To send a folder, or the output of any command, use a pipe: nothing is written to disk.

tar -czf - FOLDER | curl -N {{.Base}}/FOLDER.tgz -T -
  1. curl prints a table with the link and the commands for the receiver: send them to the receiver.
  2. Keep the terminal open: the file leaves your computer only while the receiver downloads it.
  3. The last line tells you how it went: OK when the receiver got every byte, ERRORE with the reason otherwise.

Windows: type curl.exe; in Windows PowerShell curl is an alias of Invoke-WebRequest.

SenderZip with password and send from a terminal

These examples use Bash. Replace FILE with a file, FOLDER with a folder, and choose an unused archive name.

Replace PASSWORD with your password, keeping the single quotes. The password option is -P (capital P). If the password contains a single quote, it must be escaped for Bash.

Password exposure: the password can remain in shell history and appear in process listings. Share it separately from the download link.

Create a ZIP, then send it

zip -P 'PASSWORD' archive.zip "FILE" && curl "{{.Base}}" -T archive.zip

This creates archive.zip on your computer before sending it. The server does not store it.

ZIP and send through a pipe

(set -o pipefail; zip -P 'PASSWORD' - "FILE" | curl -N "{{.Base}}/archive.zip" -T -)

Preserve folder permissions: TAR, ZIP and send through a pipe

TAR records Unix permissions and symbolic links inside the password-protected ZIP.

(set -o pipefail; tar -cf - "FOLDER" | zip -P 'PASSWORD' - - | curl -N "{{.Base}}/archive.tar.zip" -T -)

Neither pipe example writes an archive to disk. pipefail reports failures from any stage. Keep the terminal open until the receiver finishes, and share the link printed by curl.

Clear Bash history after sending

This command clears the entire history of the current Bash session and overwrites its history file:

history -c && history -w

Other open terminals can write their own history back later. This does not erase other history files, terminal recordings or system logs, and cannot undo password exposure in process listings.

For the receiver

Save the download first, then extract it in an empty folder. For either file ZIP example, save it as archive.zip and run:

unzip -P 'PASSWORD' archive.zip

For the TAR example, save it as archive.tar.zip. Extract with tar -xpf to restore the recorded Unix permissions (where the receiving filesystem supports them):

(set -o pipefail; unzip -P 'PASSWORD' -p archive.tar.zip | tar -xpf -)

Use the same password for unzip. Its lowercase -p sends the extracted TAR to the pipe; it is not a password option.

Encryption limits: standard zip uses legacy ZipCrypto, not AES, and ZIP entry names remain visible. Do not rely on it for highly sensitive files.

Install the tools

The terminal sender needs curl; the receiver needs a browser, or one of curl, wget and aria2c. The password ZIP examples also need zip and unzip; the folder examples need tar. Most systems already have curl and tar.

Debian / Ubuntusudo apt install curl wget aria2 zip unzip
Fedora / RHELsudo dnf install curl wget aria2 zip unzip
Arch / Manjarosudo pacman -S curl wget aria2 zip unzip
openSUSEsudo zypper install curl wget aria2 zip unzip
Alpineapk add curl wget aria2 zip unzip
macOS (Homebrew)brew install curl wget aria2 zip unzip
FreeBSDsudo pkg install curl wget aria2 zip unzip
Windows: wgetwinget install JernejSimoncic.Wget
Windows: aria2winget install aria2.aria2

Windows 10 and 11 already include curl.exe. For the Bash ZIP/TAR examples, use WSL and the Debian / Ubuntu installation command above.

Privacy and security

  • Nothing is stored. The file streams from the sender to the receiver. Bashtransfer holds only the bytes in transit, in memory, and never writes the file to disk.
  • Single-use links. Each link is random, works for one download and expires if nobody uses it.
    • {{- if .HTTPS}}
  • Encrypted in transit. Both connections, sender to server and server to receiver, use HTTPS.
  • Not end-to-end encrypted. HTTPS protects the file on the network, but the server sees it while relaying it. Encrypt confidential files before sending them.
    • {{- else}}
  • Not encrypted. This server is reached over plain HTTP, and the server sees the file while relaying it. Encrypt confidential files before sending them.
